# CONTRIBUTING

Спасибо за интерес к OneBar. Проект небольшой и учебный, поэтому важны понятные issue, аккуратные изменения и уважение к приватности пользователей.

## Баги

Создайте [bug report](https://github.com/croupier/OneBar/issues/new/choose) и укажите:

- версию OneBar;
- модель устройства и версию Android;
- точные шаги воспроизведения;
- ожидаемое и фактическое поведение;
- включает ли проблему разрешения контактов, клавиатуру, избранное или веб-подсказки.

Не прикладывайте чужие контакты, номера, поисковые запросы, дампы баз или логи с персональными данными. Скриншот должен быть без конфиденциальных данных.

## Идеи

Перед большой функцией создайте issue с описанием проблемы и предложенным решением. Обсудите поведение, влияние на приватность, разрешения и совместимость с F-Droid до реализации.

## Локальная сборка

Нужны JDK 17 и Android SDK API 36. Android Studio не обязателен.

1. Скопируйте `local.properties.example` в `local.properties`, если файл отсутствует.
2. Укажите `sdk.dir`.
3. Запустите `gradlew.bat testDebugUnitTest assembleDebug` на Windows или `./gradlew testDebugUnitTest assembleDebug` на Unix.
4. Для сайта выполните `cd site`, `npm ci`, `npm run build`, `npm run check`.

## Правила изменений

- Не добавляйте рекламу, платные услуги и собственную телеметрию.
- Не отправляйте в аналитику запросы, контакты, номера, пакеты приложений или устойчивые идентификаторы.
- Новое разрешение Android требует отдельного обсуждения.
- Для совместимости с F-Droid не добавляйте проприетарные библиотеки и Google Play Services.
- Соблюдайте существующий стиль Kotlin и Compose. Не делайте не связанную с задачей переработку Surrounding-кода.
- Добавляйте тесты для изменений логики. UI-изменения проверяйте на реальном устройстве, если оно доступно.
- Файлы должны заканчиваться переводом строки.

## Pull request

1. Создайте отдельную ветку.
2. Внесите минимальные изменения и добавьте тесты.
3. Обновите документацию и `CHANGELOG.md`, если изменилось пользовательское поведение.
4. Убедитесь, что тесты и сборка сайта проходят.
5. Опишите в PR, что изменено, как проверено и какие есть ограничения.

Коммиты и push выполняет владелец репозитория, если явно не попросили иное.
